API Testing Made Simple

輕量級 Mock 伺服器，支援動態延遲、錯誤模擬與 Cloudflare 等級的 Waiting Room 測試。

ALL METHODS 通用動態端點
/api/mock/dynamic
支援 GET, POST, PUT, DELETE
⏱️

網路延遲

參數 delay=3000
模擬慢速網路回應。

⏰

請求超時

參數 timeout=2000
模擬 408 Timeout 錯誤。

❌

HTTP 錯誤

參數 httpStatus=500
模擬任意狀態碼。

🎨

自定義 Wrapper

參數 code, message
修改回傳結構的屬性。

📦

自定義 Payload

參數 data
注入自定義的資料物件。

⚡

Raw Mode

參數 raw=true
不使用 Wrapper，直接回傳。

🎛️ 請求參數 (Query / Body)

參數 類型 說明
delay Integer 延遲幾毫秒 (ms) 後回傳。
timeout Integer 延遲幾毫秒後回傳 408 Timeout。
httpStatus Integer 指定 HTTP 狀態碼。支援：
400 401 403 404 409 422 429 500 502 503 504
code Integer 自定義 Wrapper 中的 code 欄位資訊 (預設 0)。
message String 自定義 Wrapper 中的 msg 欄位資訊。
data JSON 自定義 Payload 資料。
GET 請求需進行 URL Encode。
raw Boolean 設為 true 時，不使用 code/msg 包裝，直接回傳 data。

📝 使用範例

網路延遲 (200 OK) 

curl "https://mock-server.aken.life/api/mock/dynamic?delay=3000"

超時錯誤 (408 Timeout) 

curl "https://mock-server.aken.life/api/mock/dynamic?timeout=2000"

自定義回應 (POST with Delay) 

curl -X POST https://mock-server.aken.life/api/mock/dynamic \
  -H "Content-Type: application/json" \
  -d '{"code": 0, "message": "success", "delay": 2000, "data": {"userId": 123}}'

原始回應模式 (Raw Mode)

不包裝 code/msg 
curl -X POST https://mock-server.aken.life/api/mock/dynamic \
  -H "Content-Type: application/json" \
  -d '{"raw": true, "data": {"customField": "123", "list": [1, 2]}}'

預設回應結構

{
  "code": 0,
  "msg": "success",
  "data": { ... },
  "methodCode": null,
  "s1": null
}
QUEUE SYSTEM Cloudflare Waiting Room 模擬
/api/waiting-room
Stateful Queue Logic

Cookie Client Required

此功能依賴 __cfwaitingroom Cookie 來維持排隊狀態。測試時請務必啟用 Cookie (如 curl 的 -c / -b 參數)。

🎛️ 控制參數 (Query Parameters)

參數 範例值 說明
status waiting 重置狀態並開始排隊 (會產生新的 Session 綁定 Cookie)。
注意：Polling 時請勿帶此參數，否則會持續重置時間。
status allowed 強制通過 (Status 200)，不需要排隊
duration 120 設定排隊總時長 (秒)。
此設定會綁定當前 Cookie，直到時間結束前都會回傳 409。

📡 回應狀態 (Based on Queue Status)

HTTP 409 排隊中 (Waiting)

當 inWaitingRoom: true 時回傳。

{
  "inWaitingRoom": true,
  "waitTime": 60,
  "refreshIntervalSeconds": 20
}
HTTP 200 已通過 (Allowed)

當 inWaitingRoom: false 時回傳。

{
  "inWaitingRoom": false,
  "waitTime": 0
}

情境 1: 正常排隊 (60秒)

Default Flow

第一次請求會取得 Cookie，後續請求帶上 Cookie 會看到時間倒數。

# 第一次
curl -c cookies.txt -H "Accept: application/json" "https://mock-server.aken.life/api/waiting-room"

# 後續Polling (帶上 -b)
curl -b cookies.txt -H "Accept: application/json" "https://mock-server.aken.life/api/waiting-room"

情境 2: 快速通關

熱門

開發測試最常用，直接模擬「已排完」狀態。

curl "https://mock-server.aken.life/api/waiting-room?status=allowed" \
  -H "Accept: application/json" \
  -b cookies.txt

情境 3: 自定義排隊時間

例如想測試排隊 5 分鐘 (300秒) 的 UI 顯示。

curl "https://mock-server.aken.life/api/waiting-room?duration=300" \
  -H "Accept: application/json" \
  -c cookies.txt
